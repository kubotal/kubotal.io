Écosystème open source pour les plateformes Data

Kubotal présente OKDP, KuboCD et KubAuth pour couvrir la plateforme Data, la livraison GitOps et les accès Kubernetes.

Ces trois projets répondent à des responsabilités différentes. Les distinguer permet de choisir une brique sans lui attribuer le rôle de toute la plateforme.

Quel est le rôle de chaque projet ?

ProjetRôle présentéSource officielle
OKDP Distribution open source pour plateformes Data sur Kubernetes. okdp.io
KuboCD Livraison continue GitOps pensée pour les plateformes complexes. kubocd.io
KubAuth Authentification et gestion des accès pour les clusters Kubernetes. GitHub

Quand regarder OKDP ?

OKDP concerne les équipes qui cherchent une distribution de services Data déployée sur Kubernetes. La plateforme regroupe les briques nécessaires aux traitements et aux usages Data sans enfermer l'architecture dans une offre propriétaire unique.

Quand regarder KuboCD ?

KuboCD s'adresse aux équipes plateforme qui veulent emballer la complexité d'un chart Helm et exposer un contrat de déploiement plus court aux utilisateurs techniques. Flux reste le moteur GitOps qui applique les ressources générées.

Quand regarder KubAuth ?

KubAuth concerne la gestion des identités et des accès aux clusters Kubernetes. Le projet vise à éviter que l'accès repose sur des fichiers kubeconfig qui circulent entre les équipes.
